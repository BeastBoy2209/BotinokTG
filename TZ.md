Техническое задание — Telegram-бот для дружеского чата

Версия: 1.0
Тип: Telegram Bot
Язык: Go
Основная БД: PostgreSQL
Среда запуска: Docker
Пользователи: закрытая группа Telegram на 4 человека

1. Цель проекта

Разработать Telegram-бота для небольшого дружеского чата, который автоматизирует:

⏰ напоминания;
🎲 случайный выбор участника;
💰 учёт общих расходов и взаимных долгов;
📹 автоматическую обработку ссылок на TikTok, YouTube Shorts и Instagram Reels.

Бот должен работать не только через команды, но и автоматически реагировать на определённые сообщения в чате.

3. Telegram-модуль

Это основной интерфейс приложения.

Бот должен:

получать сообщения из Telegram;
определять команды;
определять обычные сообщения;
определять ссылки;
отправлять сообщения;
отправлять видео;
отправлять ошибки пользователю;
ограничивать работу ботом конкретным Telegram-чатом.
Основные команды
Команда	Назначение

/choose	Выбрать случайного участника

4. Users

Бот должен знать участников чата.

Для каждого пользователя сохраняется:

User
├── ID
├── TelegramID
├── Username
├── FirstName
└── CreatedAt

При первом взаимодействии бот регистрирует пользователя.

Ограничение

Бот предназначен для одного конкретного дружеского чата.

То есть необходимо определить:

ALLOWED_CHAT_ID

и игнорировать команды из других чатов.

5. ⏰ Reminders
Назначение

Пользователь создаёт напоминание, бот сохраняет его и отправляет сообщение в указанное время.

Создание
/remind 18:00 забрать заказ

Бот:

определяет пользователя;
определяет время;
сохраняет напоминание;
подтверждает создание.

Ответ:

⏰ Напоминание создано


18:00
Забрать заказ
Просмотр
/reminders

Ответ:

⏰ Ваши напоминания:


1. Сегодня 18:00
   Забрать заказ


2. Сегодня 21:30
   Позвонить Диме
Удаление
/cancel 1

Удаляет напоминание №1.

Модель
Reminder
├── ID
├── UserID
├── ChatID
├── Text
├── RemindAt
├── CreatedAt
└── Completed
Background Worker

Напоминания не должны проверяться только при поступлении сообщений.

Отдельный worker:

                    ┌── PostgreSQL
                    │
Reminder Worker ────┤
                    │
                    └── Telegram

Worker периодически ищет:

remind_at <= NOW()
AND completed = false

и отправляет сообщение.

Это будет одна из важных частей проекта для изучения goroutines и context.

6. 🎲 Chooser — «Кто сегодня?»
Основная команда
/choose

Бот выбирает одного участника текущего чата.

Пример:

🎲 Сегодня выбран:


Тимур
История

Бот должен сохранять результаты.

/choose

например:

Дима

Следующий раз желательно учитывать историю, чтобы распределение было более равномерным.

Статистика
/stats

Ответ:

🎲 Статистика


Тимур — 4
Дима — 2
Алихан — 1
Макс — 3
Алгоритм

На первом этапе:

participants → random → selected

На втором:

participants
      ↓
history
      ↓
выбрать участника с меньшим количеством выборов
      ↓
random среди подходящих

Это даст тебе возможность самостоятельно реализовать и протестировать алгоритм.

9. Расчёт долгов
/settle

Бот должен преобразовать общий баланс в минимальный набор переводов.

Например:

💸 Как рассчитаться:


Дима → Тимур      1 500₸
Алихан → Тимур    2 000₸
Макс → Тимур      1 000₸

После этого пользователь может отметить расчёт завершённым.

10. 📹 Downloader

Это автоматический модуль.

Бот анализирует обычные сообщения, а не только команды.

Например пользователь отправляет:

https://www.tiktok.com/...

Бот распознаёт URL.

Поддерживаемые типы:

TikTok
YouTube Shorts
Instagram Reels
Pipeline
Telegram message
       ↓
URL Detector
       ↓
Platform Detector
       ↓
Downloader
       ↓
Video
       ↓
Telegram
URL Detector

Должен уметь определить:

есть ли URL в сообщении?

Например:

"смотри что нашёл https://..."

тоже должно работать.

Platform Detector

Определяет:

TikTok
YouTube
Instagram
Unknown

Если ссылка неизвестной платформы:

❌ Эта платформа пока не поддерживается.
Downloader

Downloader — отдельный компонент.

Он получает:

URL

и возвращает:

Video

или ошибку.

Важно: скачивание должно применяться к контенту, который вам разрешено загружать и пересылать, с учётом правил соответствующей платформы.

11. Архитектура

На начальном этапе предлагаю такую структуру:

Telegram
    │
    ▼
Handlers
    │
    ▼
Services
    │
    ├──── Reminder Service
    │
    ├──── Expense Service
    │
    ├──── Chooser Service
    │
    └──── Downloader Service
    │
    ▼
Repositories
    │
    ▼
PostgreSQL
Что делает каждый слой

Handler

Отвечает за Telegram:

message → разобрать → вызвать service → ответить

Service

Содержит бизнес-логику.

Например:

ExpenseService.AddExpense()

Repository

Работает с БД:

SaveExpense()
GetExpenses()
GetBalance()

Таким образом, Telegram-код не должен напрямую писать SQL.

12. PostgreSQL

Предварительно понадобятся таблицы:

users
reminders
expenses
choose_history

Связи:

users
  │
  ├──── reminders
  │
  ├──── expenses
  │
  └──── choose_history

chat_id желательно хранить там, где данные относятся к конкретной группе. Это позволит в будущем теоретически использовать бота в нескольких чатах, не смешивая их данные.

13. Конфигурация

Не хранить токен Telegram и пароль БД непосредственно в коде.

Например:

TELEGRAM_BOT_TOKEN
DATABASE_URL
ALLOWED_CHAT_ID

Позже можно добавить:

LOG_LEVEL
TIMEZONE
14. Логирование

Использовать стандартный Go-пакет:

log/slog

Логировать:

запуск бота;
ошибки Telegram API;
ошибки БД;
создание reminder;
выполнение reminder;
добавление expense;
ошибки downloader.

Не логировать Telegram Bot Token и другие секреты.
